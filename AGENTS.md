# Repository guidance

These instructions apply to contributors and coding agents throughout this repository. Read
[the onboarding guide](docs/ai/AGENT_ONBOARDING.md), then the contract and
[task playbook](docs/ai/TASK_PLAYBOOKS.md) for the module you will change. The
[documentation index](docs/README.md) identifies the canonical reference for each area.

## Project and commands

Luminati is a 2.5D pixel-art engine built with three.js and plain JavaScript ES modules. JSDoc
types are checked by TypeScript; there are no application `.ts` files, framework, linter, or
external test runner. Textures, sprites, sounds, and music are generated at runtime.

The front ends are the launcher (`index.html`, list generated by `tools/vite-launcher.js`),
game (`game.html` → `src/main.js` → `src/game/`), editor (`editor.html` → `src/editor/`), and
standalone module checks in `sandbox/`. They share `src/engine/`; its public API is exported by
`src/engine/index.js`. Shipped content lives in `public/levels/`, `public/campaigns/`, and
`public/i18n/`.

Run commands from the repository root after `npm ci`. Node.js 24 is recommended; see the
[requirements](docs/user/GETTING_STARTED.md#2-requirements) for supported versions and browser
verification constraints.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Vite at `http://127.0.0.1:5173/`; includes the level-save API. |
| `npm run build` | Build the launcher, game, and editor into gitignored `dist/`. |
| `npm run preview` | Serve a fresh build; no level-save API. |
| `npm run typecheck` | Check JSDoc in `src/`, `sandbox/`, and `tools/`; emit nothing. |
| `npm run docs:check` | Validate documentation links, images, and anchors. |
| `npm run check -- --page=<page.html> --query=<query> --out=<unique-name> --strict` | Run browser checks and capture screenshots and a JSON report in `.check/`. |
| `npm run level:check -- <name-or-file>` | Validate a level without changing it. |
| `npm run level:check -- --campaign=<name>` | Validate a campaign, its levels, story, and links. |
| `npm run story:test`, `npm run api:test`, `npm run level:test` | Run the related Node self-tests. |
| `npm run i18n:keys`, `npm run i18n:check -- --strict --complete` | Check content keys and shipped translations. |
| `npm run i18n:test`, `npm run keys:test` | Run translation and text-key self-tests. |

Vite does not type-check. A successful build does not replace `npm run typecheck`.
The browser harness discovers standard Windows Chrome/Edge installations; set `CHROME_PATH`
for another executable. It requests ANGLE's D3D11 backend, so check browser/GPU support on other
platforms and report verification limitations. See
[testing and verification](docs/development/TESTING_AND_VERIFICATION.md) for options and scripts.

## Engineering safeguards

- Read the applicable contract: [engine](ARCHITECTURE.md),
  [level/editor](docs/contracts/LEVEL_EDITOR.md), [combat](docs/specs/GLAIVE.md) (with the engine
  additions of [COMBAT.md](docs/contracts/COMBAT.md)),
  [pixel UI](docs/specs/PIXEL_UI.md), or the feature specification in `docs/specs/`.
  Contract changes must be additive; update documentation and JSDoc or `types.d.ts` copies
  together. If a document disagrees with the implementation, check the code and correct the
  documentation rather than relying on a stale description.
- Do not add backward compatibility, migrations, aliases, or legacy-format readers unless the
  task explicitly requests them. Update shipped data with a format change and report which
  existing user data can no longer load. Current format IDs use `luminati-*`; storage keys use
  `luminati.*`.
- Keep procedural world generation deterministic with `RNG`, `hash2`, and `fbm2` from
  `src/engine/utils/math.js`. Do not rename a shipped level casually: its name seeds terrain
  noise. Change generated content in its generator, then regenerate and validate.
- Preserve byte-stable level serialization. New normalization defaults can rewrite every level;
  prefer absent optional fields, or regenerate/resave affected shipped files deliberately.
- Treat level data as untrusted. Use `isOwnKey` / `ownValue` from `src/engine/utils/own.js` for
  table lookups; reject inherited keys such as `constructor` and `__proto__`.
- Preserve coordinates and pixels: Y up; tile `(i, j)` covers `[i, i+1]` in X and `[j, j+1]` in
  Z; rows increase toward +Z; height levels use `LEVEL_HEIGHT` (0.5 world units); `PPU` is 16.
  Pixel textures use nearest magnification. Tone mapping happens once in PostFX.
- Keep point-light count fixed after warm-up, at most 12; fade intensities rather than adding,
  removing, or hiding lights. Switch shadows through lighting settings. Warm shaders against
  `postfx.sceneTarget`, and prime materials/effects that can first appear during play before
  warm-up ends.
- Use `GlobalUniforms` for shared per-frame shader state. Live weather overwrites look settings;
  tune supported weather/configuration paths rather than values it rewrites each frame.
- Keep per-level state in the level lifecycle and dispose/repoint it during campaign travel.
  Preserve room detach/attach caching, editor transactions and undo, and lazy feature lifecycles.
  Peaceful levels must create no combat state; levels without story or party must incur no
  corresponding runtime work.
- Catalog additions need builders, JSDoc types, editor support, and generator coverage. Starfall
  covers peaceful features, Cinderwatch combat, the Ferryman campaign travel/story, and the
  interiors campaign furniture. Follow the matching playbook and its checks.
- Build asset/API URLs from `import.meta.env.BASE_URL` or relative page/module URLs. Root paths
  such as `/levels/` break sub-path hosting; verify with `--base=project` and the built pages.
- Use the pixel UI kit, whole art pixels, palette, and type/layout helpers. UI text uses `t()`
  with English, Japanese, and Simplified Chinese strings. Content prose uses `loc(key, english)`;
  names use `term(name)`. Keep English identities in data and translate only at display.
- Preserve text keys through edits. The editor, generators, and `i18n:keys` create GUIDs and
  `#line:` tags; do not hand-edit or copy them. New translatable fields need extractor/key
  support. Update content tables with worklist tools; load CJK glyphs before measuring.
- Add JSDoc to public APIs. Fix type errors at their cause; cast only where the checker cannot
  follow valid code, and explain any `@ts-expect-error`. Declare lazy fields in the folder's
  `types.d.ts`, never a same-name declaration file that shadows JavaScript. Generator-imported
  modules must remain Node-safe.

## Content and verification

The six level/campaign generators are `tools/make-starfall-vale.mjs`, `make-sample-hamlet.mjs`,
`make-cinderwatch-pass.mjs`, `make-gildhaven.mjs`, `make-ferrymans-lantern.mjs`, and
`make-emberfall-interiors.mjs`. Use `--check` to verify committed output or `--out=<scratch-path>`
to inspect changes. The interiors generator reads Emberfall, so an Emberfall edit may require
regenerating that campaign too. Never hand-edit generated output.

Before finishing a code change, run `npm run typecheck`, relevant Node/browser checks, and
`npm run build`; update documentation the change invalidates and run `npm run docs:check`.
For documentation-only changes, run the documentation check. Read browser reports and view
screenshots: a clean exit code alone does not prove correct rendering. Use `--strict` when the
page should have no console errors, warnings, failed requests, or throwing action-script steps.

Rendering or level-building changes require before/after fingerprints and level round trips
([playbook 16](docs/ai/TASK_PLAYBOOKS.md#16-regression-check-before-you-finish)). UI changes need
the relevant page at 1280 × 720, 1920 × 1080, and 1024 × 768, including Japanese and Chinese.
Text/display changes need key/translation checks and both content tours. Run GPU timing and
frame-gap checks without competing GPU work; record hardware and browser with measurements.

## Working tree and local files

Inspect the working tree before editing and preserve changes outside the task. Untracked levels
and campaigns may be a contributor's own content; do not edit, regenerate, delete, or commit
them without authorization. Scripted editor saves write real files through the dev API: use
unique temporary names, clean up only files you created, and never save tests as `Untitled`.

Do not assume a particular branch, remote, operating system, shell, or contributor identity.
Follow the task's authorization for commits and publication; coding agents must not commit or
publish automatically. Do not skip hooks, rewrite others' history, or add AI authorship trailers
by default. Use accurate attribution when requested or required.

Write LF line endings as specified by `.gitattributes`. Keep `node_modules/`, `dist/`, `.check/`,
logs, temporary test levels, credentials, and personal machine configuration out of commits.
`.check/` is disposable local evidence: use unique output names and never require its contents
in published documentation. Report checks run and any checks blocked by the environment.
