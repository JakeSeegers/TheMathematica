Architecture Diagrams

Six hand-drawn figures of how Luminati is put together: who imports whom, what one frame runs, how a frame is rendered, how a level file becomes a diorama, how the editor keeps its views in sync, and how at most 12 point lights serve the 95 light sources of a big level. The prose versions (with every number checked against the code) are in OVERVIEW.md, RENDER_PIPELINE.md and PERFORMANCE.md.

1Module dependencies

Applications depend on the engine; the engine depends only on its foundation and three.js — never the other way round.

2The frame loop

One Engine tick in the game: systems by order, then the late pass, then the shared time, then PostFX — and which step writes which global uniform.

3Render pipeline

The scene renders once into a linear HDR multisampled target; depth of field works at half resolution; tone mapping happens exactly once, in OutputPass.

Scroll the figure sideways on a narrow screen.

4Level build pipeline

A level is plain JSON: it is normalised, then World.build turns it into a scene in nine steps, wiring every built object's descriptors into the systems that own them.

Scroll the figure sideways on a narrow screen.

5Editor data flow

Every edit goes through EditorState in a transaction; the views only translate input and redraw from change events.

Scroll the figure sideways on a narrow screen.

6LightPool assignment

Twelve real point lights serve every lantern of a big level: the ones near the player and in view get them, and a light only ever moves while it is dark.
