## 1. What a campaign is

A campaign is one folder: `public/campaigns/<name>/`, with `<name>` a file-safe slug
(`a–z`, `0–9`, `-`, at most 60). It holds

```
public/campaigns/<name>/
  campaign.json          the levels, where they sit, where the game starts, the chapters, starting flags
  levels/<id>.json       the campaign's own levels (luminati-level files) — chapter variants too
```

Each level is one place of the story (a town, a road, a dungeon floor) and an ordinary
`luminati-level` file ([LEVEL_FORMAT.md](LEVEL_FORMAT.md)): it opens in the editor, plays on its own
and passes `level:check`. Played on its own (`?level=`), a level ignores its exits and entrances
and keeps every object; played in its campaign, it travels.

`campaign.json` names levels by **id**, never by path: level `<id>` is the file
`levels/<id>.json` of the same folder. Every file a campaign can load therefore lies inside its
folder, whatever the file says (a campaign file is untrusted input, like a level). Standalone
levels stay in `public/levels/`; a campaign cannot use them (copy one into its `levels/`).

## 2. `campaign.json`

```json
{
  "format": "luminati-campaign",
  "version": 1,
  "name": "The Ferryman's Lantern",
  "subtitle": "A Luminati campaign",
  "title": { "title": "THE FERRYMAN'S LANTERN", "subtitle": "A short tale of Millbrook", "credit": "Luminati 2.5D Pixel-Art Engine · three.js" },
  "start": { "level": "millbrook", "entrance": "" },
  "levels": [
    { "id": "millbrook", "at": [0, 0] },
    { "id": "mill-road", "at": [40, 8] },
    { "id": "old-quarry", "at": [96, 2] },
    { "id": "mill-cellar" }
  ],
  "chapters": [
    { "id": "the-flood", "title": "Chapter One", "subtitle": "The Broken Ford",
      "textKeys": { "title": "584273F049EDEB5C43FFF023ABC397D4", "subtitle": "4F2D24DCCC01D2B1EE348EF102CAE518" } },
    { "id": "lanterns-home", "title": "Chapter Two", "subtitle": "Lanterns Home", "when": "lantern-found", "levels": { "millbrook": "millbrook-dusk" },
      "textKeys": { "title": "1EBA4F29C036486BAE79B3B8AA57F2FE", "subtitle": "2D1E7B6A3302575E219AB56949AF790A" } }
  ],
  "story": ["main.json", "dialogue.story"],
  "textKeys": { "subtitle": "…", "title.title": "…", "title.subtitle": "…", "title.credit": "…" }
}
```

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `format` | `"luminati-campaign"` | (required) | Anything else is an error. |
| `version` | integer | 1 | Newer than the engine: a warning; unknown fields are ignored. |
| `name` | string | `"Untitled campaign"` | The title screen's title (upper-cased unless `title.title`), the world map's title, the save's label. |
| `subtitle` | string | `""` | The title screen's subtitle (unless `title.subtitle`). |
| `title` | object | `{}` | Title-screen overrides `{ title, subtitle, prompt, credit }`, like a level's `environment.title`. |
| `start` | `{ level, entrance }` | the first level, `""` | Where a new game begins: a level id and an entrance name (`""`: the level's player start). |
| `levels` | `[{ id, at? }]` | (at least one) | The campaign's levels. `id`: a slug (the file `levels/<id>.json`). `at`: `[x, z]`, where the level's corner (0, 0) sits on the campaign plane ([§3](#3-levels-the-campaign-plane-and-seams)); absent: not placed. |
| `chapters` | `[{ id, title?, subtitle?, when?, levels?, textKeys? }]` | `[]` | Stages of the story ([§5](#5-story-flags-conditions-chapters)). `levels` maps a level id to a variant file id. `textKeys`: the text keys of the chapter's `title` and `subtitle`. |
| `flags` | string[] | `[]` | Story flags set when a new game begins. |
| `story` | string[] | `[]` | The story files, in the campaign's `story/` folder (`main.json`, `dialogue.story`): items, quests, actors, shared scripts, campaign events, start presets — [STORY_SCRIPT.md §8](STORY_SCRIPT.md#8-story-files). |
| `textKeys` | object | absent | *(Optional; additive, October 2026.)* The text keys of the campaign's own texts: `subtitle` and `title.title`, `title.subtitle`, `title.prompt`, `title.credit` for the `title` overrides. |

Every text a player reads carries a **text key**, a GUID that keys its translation
([I18N.md §4.2](I18N.md#42-keys-and-lookup)): `campaign.json`'s own texts and each chapter's in
`textKeys`, the level files' as in any level, the story files' in their items' and quests'
`textKeys` and their scripts' `#line:` tags ([STORY_SCRIPT.md §8](STORY_SCRIPT.md#8-story-files)).
The keys are made by the campaign's generator, the editor or `npm run i18n:keys`, and kept through
every edit. A chapter variant shares its base's keys where its English is the same; a changed line
has its own key. The loader cleans `textKeys` (a malformed key or an unknown field is dropped with
a warning; a key of lower-case digits is written in upper case, silently); the campaign's chapter
keys are cleaned but not bounded by their texts.

Keys this engine does not know are kept by `normalizeCampaign` (`extra`) and written back by
`serializeCampaign`, so a rewrite by an older engine loses nothing — except `__proto__`,
`constructor` and `prototype`, which are never copied (as in a level file: they would change the
object's prototype rather than add a field).

`normalizeCampaign` fills the defaults and drops what cannot be used, with a warning each: a level
id that is no slug or is listed twice, an `at` that is not two numbers, a chapter entry that is no
object, a variant of an unknown level or with a non-slug id, a story file name that is no name, more
than 64 story files. The file is untrusted data: a warning shows any value without converting it
(`{"toString": 1}` is shown as JSON, never passed to `String()`). **Errors** (the game refuses to start,
`level:check` fails): a `format` other than `luminati-campaign`, no levels, a `start.level` that is
not listed. `serializeCampaign` writes the normalised fields in a fixed order with a two-space
indent (an `at` pair on one line) and a final newline; generators use it, so `--check` compares
byte for byte.

## 3. Levels, the campaign plane and seams

Levels with `at` lie on one shared plane in world units (1 unit = 1 tile): level `L` at `[ax, az]`
covers `x ∈ [ax, ax + width]`, `z ∈ [az, az + depth]`. Two placed levels that **touch** (one's
east edge on the other's west edge, or north / south) or **overlap** join seamlessly:

- **Crossing a seam.** An exit with no `entrance` leads across the seam: the player's position is
  mapped through the plane into the target level (`acrossSeam`), clamped onto its map, moved out of
  the exit it lands in (the way back) toward the inside by 0.9 u, then onto the nearest standable
  spot within 3 u. A road that leaves Millbrook at z 15–18 enters Mill Road at the same plane z,
  i.e. its own rows 7–10, keeping the player's facing. A travel from far from any seam (a script)
  lands at the player start instead.
- **Matching edges.** Where levels touch, the edge tiles should agree — the road walkable on both
  sides at the same height; where they overlap, the shared tiles should be the same.
  `level:check --campaign` warns about tiles that do not ([§9](#9-checks)).
- **The world map.** On a placed level the world map (N / Tab) shows every placed level on its
  place ([§6.6](#66-the-world-map)).

Unplaced levels (interiors, dungeons) are reached through entrances only, and the world map shows
them alone.

## 4. Exits and entrances

Both are catalog types with `campaign: true` ([OBJECT_CATALOG.md](OBJECT_CATALOG.md#exit)); the
editor places, draws and checks them like regions and point markers.

- **`exit`** (a rect): `to` (a level id of the campaign), `entrance` (a name in that level, or
  blank), `mode` (`walk` | `use`), `label` (a `use` exit's prompt verb), `requires` (a story flag or
  condition — the flag rule of [§5](#5-story-flags-conditions-chapters)), `locked` (what the player
  reads without it).
  - **walk**: stepping into the rect travels. An exit fires only once the player has stood outside
    every exit since arriving or since a refusal, so an arrival inside an exit (or a closed walk
    exit) does not bounce.
  - **use**: an interactable at the rect's centre (prompt `label` 1.7 u above it, reach ≈ half the
    rect's diagonal + 0.3, at least 0.9); Space travels — a door, a stair, a cave mouth.
  - **requires**: checked every time; without the flag the player reads `locked` (default "The way
    is closed.") and stays.
- **`entrance`** (a point): `name` (blank: its id) and `facing`. The player arrives there, facing
  `facing`.

**Where the player arrives** (`CampaignRuntime.arrival`): the exit's `entrance` in the target
level; else across the seam when both levels are placed and the mapped point is within 3 u of the
map; else the target's player start (`spawn`). An entrance an exit names but the target lacks: a
console warning and the player start.

**Fetching and building ahead.** While the player is within 12 u of an exit, its target level's
file is fetched (once; parsed again on every load), and the level behind the nearest of them whose
`requires` holds is **built ahead** — parsed, the story applied as it stands in that level, its
world built in slices of the page's idle time between frames, nothing of it in the running game
until the travel attaches it ([§6.3](#63-switching-levels); KNOWN_ISSUES CMP-01). One level at a
time; it is dropped when the player turns to another exit or goes farther than 24 u from every
exit toward it, and begun again when the story changes what the level holds. A level **set aside**
(the town while the player is in a room, the last room — [§6.3](#rooms-the-levels-set-aside)) is
not built ahead: the travel attaches it as it is.

## 5. Story: flags, conditions, chapters

The story itself — conditions, scripts, events, talk scripts, actors, items, quests, cutscenes,
the journal — is [STORY_SCRIPT.md](STORY_SCRIPT.md). What it means for a campaign's levels:

**Story flags** are names (`bridge-mended`; letters, digits, `_ . -`) — flags are variables whose
value is 1. They are set by

- scripts (`set`, `clear`, `var`: talk scripts, events, the story files' scripts);
- a villager's optional `flag` field, when a conversation with them ends;
- `campaign.json`'s `flags` and the story files' `vars`, when a new game begins;
- the `__game.campaign.setFlag` and `__game.story.set` hooks (tests).

They are read by **conditions** ([STORY_SCRIPT.md §3](STORY_SCRIPT.md#3-conditions)). Exits'
`requires`, objects' `when` / `unless` and chapters' `when` keep the **flag rule**: one bare name is
that flag, as before (a reserved word there — `when: gold` — is a flag that can never be set: an
error of the checks; write `gold > 0`). Events' `if` and quest goals' `done` read a condition as
scripts write it (`if: gold` reads the purse).

- **exits' `requires`** — live: the exit opens the moment the condition holds
  (`requires: item:cellar-key` in the demo);
- **every object's `when` / `unless`** (`STORY_FIELDS`, optional, no default): the object is there
  only while `when` holds, and gone while `unless` holds. Villagers, exits, entrances, events,
  markers, regions, critters, particle areas and every prop — houses, windmills, wells and
  waterfalls too — come and go **live**, while the player watches (Mill Road's bridge appears in
  Hollis's cutscene, its flood debris vanishes); the combat objects (enemies, chests, waystones)
  follow their conditions **when the level is entered**
  ([STORY_SCRIPT.md §9.5](STORY_SCRIPT.md#95-objects-that-come-and-go));
- **chapters' `when`**, events' `if`, quest goals, script `if`s and options.

**Chapters.** The chapter in force is the last one whose `when` holds (a chapter without `when`
always counts). Its `levels` map swaps a level for a variant file: from then on, entering
`millbrook` plays `levels/millbrook-dusk.json`. A variant must keep its base level's size and the
entrances other levels' exits name (`level:check --campaign` checks every variant). When a flag begins a new chapter, a
banner shows its `title` and `subtitle`. Exits always name the base level id, never a variant. A
chapter's `when` cannot read `chapter` — the chapter in force is what those conditions decide (an
error of the campaign check); should one do so anyway, `activeChapter` answers that inner question
with the chapter decided so far (the last earlier chapter whose `when` held, else the first
chapter) instead of asking again forever.

## 6. In the game

### 6.1 Starting

| URL | What plays |
| --- | --- |
| `game.html?campaign=<name>` | The saved game in this browser, else the start. The title shows the campaign's title; with a saved game, **Continue** / **New journey** (←/→, Enter). |
| `…&autostart=1` | Skips the title (continues the saved game, or starts). |
| `…&new=1` | Forgets the saved game and starts over. |
| `…&level=<id>[&entrance=<name>]` | Starts in that level (a fresh story; the entrance, else its player start). A chapter variant id plays as the level it stands for. |
| `…&level=local:<slot>&as=<id>` | Plays the level in browser slot `<slot>` as level `<id>` of the campaign (the editor's play-test); `<id>` may be a variant. |
| `…&story=<preset>` | A new game starts from a debug start preset of the story files (its level, entrance, variables, items, quests, gold — [STORY_SCRIPT.md §8](STORY_SCRIPT.md#8-story-files)); with `&new=1` (or without a save). |

The launcher (`index.html`) lists every campaign folder with a current `campaign.json`: its name,
the title screen's subtitle, its level and chapter counts, Play (`game.html?campaign=<name>`) and
an Edit link per file in its `levels/` (`editor.html?open=<name>/<level>`;
[LEVEL_STORAGE_API.md §6](LEVEL_STORAGE_API.md#6-published-levels-and-url-resolution)).

A `&level=` start (and so every editor play-test) saves under its own key
(`luminati.campaign.<name>.test`): testing a level never overwrites the real saved game.

A chapter variant started as its level (`&level=<variant>`, `&as=<variant>`) plays the variant's
text under its base level's id: `state().campaign.file`, the save and travel keep the base id, but
the game's `source` is the variant's file (`CampaignLevels.textPath`), so its texts are shown by the
keys of the variant's own file (shared with its base where the English is the same), as when the
chapter switches to it ([I18N.md §4.8](I18N.md#48-call-sites)).

### 6.2 The title

`CampaignRuntime.titleOptions`: `campaign.title` overrides, else `name` upper-cased and `subtitle`.
With a saved game the title offers Continue / New journey (`TitleScreen` `destinations` with the
hint "Continue or begin again"); New journey forgets the save and travels to the start before play.
Titles longer than the screen shrink to fit.

### 6.3 Switching levels

`CampaignRuntime.travel(to, { entrance })`:

1. The player is held; the target file is fetched (or was fetched ahead); the screen fades out
   (0.35 s).
2. The story is applied to the loaded level (chapter variant, `when` / `unless`) and the arrival
   point computed ([§4](#4-exits-and-entrances)). A level built ahead from the same file is used
   when every story-conditioned object of the file is there or not exactly as it was when its
   build began (its *presence key*); otherwise it is dropped and the level built as below.
3. The level being left reports what the campaign keeps (combat progress, opened chests, the
   enemy groups defeated).
4. `Game.swapLevel` switches without a reload ([Campaign lifecycle](CAMPAIGN_FORMAT.md)):
   the engine, renderer, post-processing, audio, UI, weather (its rain and snow emitters), the
   texture library and **one fixed pool of the 12 point lights** stay; the old level is detached
   — combat disposed at once, so its HUD and bindings are gone before a next combat level installs
   its own — the new level is built by `_buildLevel` (the level half of `init`; a level built ahead:
   its remaining build steps run and its world is attached there, the same scene and programs as a
   world built there), the old world is
   disposed only once the new one exists (programs both use stay compiled), and init's warm-up
   runs behind the fader: rain and snow on, the bursts the level uses, the combat FX, every program
   compiled, five frames drawn. No program compiles after the fade-in (the tour checks it).
5. The level's environment is applied ([§6.4](#64-entering-a-level)), the game saved, the screen
   fades in (0.5 s), the level's banner shows and its `arrive` events run.

If the new level fails to build, the game builds the level the player left again and puts them
back where they were (a toast says the way could not be opened). A travel from a story script goes
on in the new level ([STORY_SCRIPT.md §9.1](STORY_SCRIPT.md#91-runs)); the `__game.campaign.travel`
hook waits for a script that is running to end first.

With the level built ahead, the demo's travels take ≈ 0.54–0.57 s from the fade-out to the
fade-in on the reference desktop GPU (medians; the fade-out is 0.35 s of it; before: ≈ 0.78–0.87 s, the first
of a session up to 1.5 s), and the 128 × 128 Gildhaven played as a campaign level ≈ 0.70 s
(before: ≈ 2.1–2.6 s); built at the travel they take as long as before
([PERFORMANCE.md §2.7](../architecture/PERFORMANCE.md#27-campaign-travel)).

#### Rooms: the levels set aside

A **room** is a level with `environment.interior: true` (absent by default;
[LEVEL_FORMAT.md](LEVEL_FORMAT.md)) — a house's ground floor, its upper floor, a cellar, reached
through `use` exits at doors and stairs. Inside a room there is no forest border, outer scenery,
god rays or weather ([§6.4](#64-entering-a-level)), and walking in and out is a light switch, not a
level build: the campaign keeps the levels around rooms **set aside** — detached from the running
game, nothing disposed — and attaches them again when the player comes back.

| Travel | What happens |
| --- | --- |
| from a level A into a room B | A is set aside as the **parent** — unless A is a combat level (never kept: it is released as before) |
| from a room A to any level B | A is set aside as the **last room** (at most one: an older last room is released) |
| to a level that is set aside | it is attached again instead of built — while its file (the chapter's variant, `CampaignRuntime.fileFor`) and the file's text are the ones it was built from, and the story gives the same objects from it (`storyLevel`); otherwise it is released and the level built as usual |
| to a level that is neither a room nor set aside | everything set aside is released first (a new neighbourhood) |

So at most two levels are set aside (the parent and the last room) besides the one played: the
town while the player is in its rooms, and — back in the town — the room they just left (or the
other floor, going up and down stairs). A level set aside keeps its world (`World.detach`: its
root, emissive registrations, emitters, god-ray shafts and the prompts others added taken out of
the running game; its lights handed back to the shared pool on attach), its traveler, villagers,
critters and their sprite sheets, the contact-shadow batch, the ambience's view of it and its
painted map (painted again only when the story has other objects there now). The villagers and
animals go on from where they were when the player left. What the story changed meanwhile — a flag
set in the cellar that brings a bridge, sends a villager away or opens an exit in the town — is
applied when the level is attached (every catalog type is live: `StoryRunner.applyPresence`,
`World.applyStory`), as it would be while the player watches. Its programs stay compiled while its
materials live, so the attach compiles nothing and needs no warm-up (two frames behind the fader).

The level built ahead ([§4](#4-exits-and-entrances)) is skipped for a target that is set aside.
Saves and Continue are unchanged (Continue builds the saved level as before; nothing set aside
survives a reload), and so is a new journey (it releases everything set aside). A travel that fails
releases the level left and the level being attached (set aside or not) and builds the level left
again from its file (the toast says the way could not be opened); no copy of either stays in the
scene. The game's end releases everything set aside. `state().campaign.aside` lists what is set
aside, `stats.kept` / `lastKept` / `lastAside` / `dropped` count it
([AUTOMATION_API.md](AUTOMATION_API.md#36-window__gamecampaign-campaigns-only));
`__game.game.campaign.keepRooms = false` turns it off and releases the levels set aside now.

**The example:** *Emberfall — Open Doors* (`game.html?campaign=emberfall-interiors`,
[design page](../design/campaigns/emberfall-interiors.md), generated by
[`tools/make-emberfall-interiors.mjs`](../../tools/make-emberfall-interiors.mjs)) is Emberfall with a
room behind each of its seven doors and a floor above three of them — ten rooms: a `use` exit
"Enter" over each door step with an entrance on the step for the way back, a "Go out" exit over
each room's door gap, "Go upstairs" / "Go downstairs" exits at the `staircaseFoot` of each
`staircase`, every room flagged `interior` with the room look, the walls custom legend tiles in
the building's own wall texture (cap included, so the cut top reads as wall, not floor). Its tour
`sandbox/campaign.open-doors.json` walks every door and stair there and back.

On the reference desktop GPU a room ↔ town travel then takes ≈ 0.38–0.41 s from the fade-out to the fade-in,
the fade-out's 0.35 s and ≈ 5–25 ms of work (≈ 0.45 s when the story changed what the town shows
meanwhile and its maps are painted again), however quickly the player turns round — for the demo's
Millbrook (40 × 32; before: ≈ 0.6–0.7 s) and for the 128 × 128 Gildhaven standing in for it
(before: ≈ 0.7 s after waiting 2 s by the stairs, 1.1–1.4 s leaving at once)
([PERFORMANCE.md §2.7](../architecture/PERFORMANCE.md#27-campaign-travel)). The price is memory: a
128 × 128 town set aside keeps its meshes, textures and programs while the player is in its rooms.

### 6.4 Entering a level

- **Clock.** A level with a running clock goes on from the campaign's hour (a level's `timeOfDay`
  applies only where a game starts). A level with its **own hour** (`environment.clock: false`: an
  interior, a set piece) shows its `timeOfDay` while the campaign clock pauses; the next level with
  a running clock goes on from the hour the player left at.
- **Weather.** The campaign's weather goes on, unless the level sets one of its own
  (`environment.weather` other than `clear`); a level with its own hour also keeps its own weather
  (`clear` by default) and the campaign's comes back outside. A **room** (`environment.interior`)
  shows no weather at all — no rain or snow, no snow cover, no overcast grey — whatever its own
  `weather` says, while the campaign's weather goes on (`state().weather`; `weatherShown` is
  `clear`): R changes it outside ("Rain outside"), story conditions read it (`weather`), the save
  keeps it, and it shows again in the next level outdoors.
- **Music.** `environment.music: false` stops it; otherwise it plays (again, after a silent level)
  unless the player turned it off with M (a combat track left behind returns to the village song).
- **Backdrop.** `environment.backdrop` (`void` or `#rrggbb`) replaces the sky round an interior: no
  sky, the fog and the background that colour (the mill cellar uses a dark one).
- **Fog.** The fog starts at the level's own camera distance − 7 (`environment.camera.distance`,
  default 30 → 23 units; the mill cellar, 20 → 13): a shader uniform set on every travel, so a
  change compiles nothing.
- **Combat.** A combat level gets a new `GlaiveCombat`; the player's progress — level, XP, gold,
  draughts, upgrades, wares bought — carries over from earlier combat levels (`exportProgress` /
  `importProgress`), and chests opened on an earlier visit stay open and empty. **An enemy group
  defeated there stays defeated** — every foe of it fallen, its boss's adds aside; a group fought
  only in part comes back whole — until the player rests at a waystone there, which brings the
  fallen back in place as it does within a visit: on entering, the groups the save remembers
  (`cleared`) are simply not there (`GlaiveCombat.markGroupsCleared`: no death, drop, XP, `kill`
  event — so no `cleared` event — or effect), and a defeated boss stays defeated (its arena
  open, off the maps; a rest never brings a boss back). The list is taken from the level as it
  stands whenever the campaign saves there or the player leaves (`defeatedGroups`): a rest takes
  its groups off it. Enemy groups, chests and waystones follow their `when` / `unless` live
  ([STORY_SCRIPT.md §9.5](STORY_SCRIPT.md#95-objects-that-come-and-go)): every one is loaded,
  present or not, so a level whose enemies the story has all away still plays with combat.
  Leaving restores the peaceful key bindings, HUD and camera and releases the burst pools only
  combat made (`Particles.releaseBurstPools`): the next, peaceful level has its own program
  count.

### 6.5 What stays between levels

The story (variables, items and gold, quests, the `once` events done, the turns of `cycle` /
`seq` / `pick`, visit counts by actor or `<level>/<villager>`, the day, where a script sent a
villager to live), combat progress, opened chests, the enemy groups defeated (until a waystone
rest there), the visited levels, the hour and the weather. Villagers and critters start over on
every visit — villagers at their level-file places, except where a script's `home` put them (the
story's per-level memory); a pack fought in part comes back whole. A level set aside around a room
([§6.3](#rooms-the-levels-set-aside)) is the exception: its villagers and animals go on from where
they were when the player left (a villager a script gave a `home` is put there again).

### 6.6 The world map

On a placed level, the world map shows the whole campaign: every placed level's painted map on its
place on the plane, the ones not visited yet dimmed, every level named, the current level's
regions, the player, villagers and markers where they are (`WorldMap.setMap` with `origin`). The
other levels' maps are painted in the background after a level loads. An unplaced level shows its
own map; the minimap always shows the level itself.

## 7. Saved games

One saved game per campaign and browser: `localStorage` key `luminati.campaign.<name>` (a `&level=`
start, i.e. an editor play-test: `….test`), JSON, **version 2**:

```
{ version: 2, story: { vars, items, itemNames?, gold, quests, done, counters, visits, day, levels, ending?, pending?, seed?, party? },
  level, at: { x, z, facing }, via?: { from, entrance }, time, weather, combat, opened, cleared,
  visited, chapter, savedAt, playTime }
```

- **Per level.** `opened` (base level id → the chests opened there) and `cleared` (base level id →
  the enemy groups defeated there, `GlaiveCombat.defeatedGroups`, taken whenever the game saves in
  that level or leaves it; a waystone rest there empties it but for a defeated boss; an empty list
  leaves the key out). `cleared` is additive to version 2: an older engine keeps it as an unknown
  field and writes it back. On load only levels of the campaign keep a list, of text ids (≤ 200
  characters, each once, at most 4 096).

- **When.** After every travel, when the story changes (not while a script runs) and when the page
  is hidden or left (`visibilitychange`, `pagehide`) — never before the game has started (a page
  hidden during the loading screen saves nothing).
- **Runs are atomic.** While a story script runs, a save writes the game as it was when the script
  began; the script's end saves the result. The event runs queued or going on are saved in
  `story.pending` (`event:<level>.<id>`, `story:<id>`, the conversation going on as
  `talk:<level>/<villager>`) and run again on Continue, which runs no `arrive` events ([STORY_SCRIPT.md §9.3](STORY_SCRIPT.md#93-state-and-saves)).
- **The clock.** `time` is the campaign's hour (in a level with its own hour: the hour outside).
  A continued game sets it without counting the jump as time passing (no day, no `time` events).
- **Untrusted.** Every field is checked on load (names must be names, numbers are clamped, at most
  4 096 entries per map); a level the campaign no longer has — or whose file cannot be loaded —
  starts at the campaign's start.
- **Versions.** A save of an older version (or of none), or one that is not a JSON object, is not
  read: a new journey starts (the title offers no Continue) and its first save writes over it.
  Fields this engine does not know are written back as they are (not `__proto__`, `constructor` or
  `prototype`, which are dropped); a save of a newer version is never written over.
- **Backup.** A travel's save first keeps the save it replaces as `….prev` — the game shortly
  before the last travel (other saves leave the backup as it is); a save that cannot be parsed
  falls back to it. `story.seed` is the journey's seed for `pick` (random on a new journey).
  A save the browser refuses (storage full or off) shows a toast once.
- **Story texts and names.** `story.quests.<id>` is `{ state, stage, log, title?, texts?, keys?,
  src? }`: a script's own title and stage texts, in English with their values filled in, and per
  stage the text's content key and its English before the values (`keys`, `src`), which the journal
  translates it by (I18N.md §4.5). `story.itemNames` (absent when empty) maps an item id to the name
  a shop gave an item no story file declares, so the journal shows that name, not the id's title
  case. Both are optional: a stage text without a key shows as saved, in English (a `nokey` miss), an
  item without a name shows its id in title case. On load the pairs are kept only for stages the save has a text
  for, and only a key that is a GUID: a key that is not one is dropped together with its English,
  so that text shows as saved, in English. An item name is plain text of at most 200 characters.
- **The party.** `story.party` (absent while nobody is in it) holds the player's party members as
  records — villager id, name, actor, look, class, combat rule, the level they joined in
  ([PARTY.md §2](PARTY.md#2-records-and-saves)); a run's save holds them as they were when it began.
  On load a record whose id is no name, or a second one with the same id or actor, is dropped, the
  rest repaired (class, rule, look; at most 3); Continue and a new journey bring the party in line
  with them (`Game.syncParty`).
- **New journey** and `&new=1` delete it (and its backup).

## 8. Editing a campaign

- **File › Open** lists, under the project's levels, every campaign's levels (`Campaign · <name> —
  public/campaigns/<c>/levels/`); `editor.html?open=<campaign>/<level>` opens one.
- **Save** writes the file back; **Save As** offers the **Campaign folder** (beside its siblings).
  The editor never creates a campaign: make the folder and `campaign.json` by hand or with a
  generator, then save levels into it.
- **Play-test** (F5) of a campaign level plays it inside its campaign
  (`?campaign=<c>&level=local:__playtest__&as=<level>`): its exits lead to the campaign's other
  levels (their files). **Open saved level in the game** does the same with the saved file.
- **Check for problems** lists an exit without a target or over no walkable ground, duplicate
  entrance names (two story variants of one entrance may share a name) and entrances off walkable
  ground (`travelIssues`), and the level's story problems checked against the campaign's story
  files (`storyIssues`); its "walkable ground reaches the map edge" warning skips tiles inside
  exits.
- **The story**: talk scripts, events, markers, conditions and View › Story preview —
  [STORY_SCRIPT.md §10](STORY_SCRIPT.md#10-checks-the-editor-tests) and the editor guide. The
  story files themselves are edited as text (or written by a generator); the editor reads them for
  its checks.
- The dev-server API ([LEVEL_STORAGE_API.md](LEVEL_STORAGE_API.md)): `GET /api/campaigns` (every
  folder with a `campaign.json`, with its levels) and `GET|PUT|DELETE
  /api/campaigns/<c>/levels[/<level>]` under the `/api/levels` rules. A folder without
  `campaign.json` is 404; the API never creates one.

## 9. Checks

`checkLevel` (every `level:check` and generator run) checks a level's exits and entrances on its
own: an exit with no `to` or over no walkable ground, duplicate entrance names, an entrance off the
map or not standable within 0.75 u (errors); an exit that cannot be reached from the spawn or an
entrance (error); an entrance from which no exit can be walked to (warning). The walk starts from
the spawn **and every entrance**. It also lists the level's story problems (`storyIssues` in
[`StoryChecks.js`](../../src/engine/level/StoryChecks.js), lines starting `story:`): a script line,
`when` / `unless` / `requires` or event `if` that does not parse, a reserved word as a bare flag in
`when` / `unless` / `requires` (`when: gold`), an event without what its trigger needs, a line of
a background event's script that a background run may not play — dialogue, a `choice`, `camera` …
([STORY_SCRIPT.md §6](STORY_SCRIPT.md#6-events-and-triggers)) (errors, with the script line); a
speaker, actor or place the level does not have (compared in any case, as the game finds them), a
story actor no villager of the level is (`walk` stops the script there), a `done:` that names no
`once` event or block, a `once` / `cycle` key two scripts share, `call` without a campaign's story
files, an event's `background` that is not true / false (warnings).

**Story states.** Where the objects' `when` / `unless` apply — every level of a campaign (also a
file in a campaign's `levels/` folder checked alone), a single level with a story — `checkLevel`
does not see every object at once. It takes the tests those conditions make (`bridge-mended`,
`item:plank >= 3`, `quest:find-ilse = done`), each read either way: `x != v` is `not (x = v)`, and
against a number or a word — which the game turns into a number: a stage, a variable —
`x < v` is `not (x >= v)` (`stage:find-ilse < bridge-fixed` is `not (stage:find-ilse >=
bridge-fixed)`); a count compared with 1 is the count standing alone (`item:plank >= 1`,
`visited:mill = 1`). It tries every combination of their outcomes that one story can produce, with
the values a story can give: `visited:` and `done:` are 0 or 1; items, visits, stage numbers, gold
and the day (from 1) whole numbers — `day > 2` and `day < 3` never hold together; the hour any
number from 0 to 24; flags and variables any number (`var x = 1.5`: a flag is a variable `set`
makes 1, so `x` and `x = true` can differ); quests one of their four states; the chapter, level and
weather words. A word on the right that stands for a number (`gold >= inn.price`) is free against
the value's other tests. Then it checks the level once per **story state** — each distinct set of
objects that are there ([`StoryStates.js`](../../src/engine/level/StoryStates.js) `storyStates`).
Entry-only and live types count alike. Objects whose presence changes no other object's checks —
events, markers, lights, particle areas, critters, wall torches, waterfalls, enemies — split
nothing (their own checks run in every state). A level without conditions gets the report it
always had.

The tests fall into independent **groups**: two tests that one object's condition makes, or that
read one value, are in one group. Each group's combinations are all tried (up to 12 tests in a
group; past that all off, all on and each one alone flipped from either), and the states are the
combinations of what each group can have there — six objects with flags of their own are 64
states, however many tests each flag's condition makes. Every state is checked up to a bound: 64
on a 128 × 128 level, more on a smaller one as its walk grid is smaller (up to 256; `checkLevel`'s
`maxStoryStates`). Past it a sample is checked — every group at its fullest and its emptiest, each
group's every pattern with the others at either, then an even spread (the same every run) — and
the info line says so ("story states: 256 checked — … not every combination was tried (there are
2048 states, more than the 256 checked)"). From a sample nothing is claimed for every state: what
none of the states checked reaches is a **warning** ("exit east (→ next) cannot be reached from the
spawn or an entrance in any of the 256 story states checked (not every combination was tried)"), a
pocket too (also with `--strict`), and findings of some states say "in some of the story states
checked" instead of naming them.

The first state is checked in full; the others reuse its work wherever nothing that differs is
near: the walk grid's heights are worked out again only round the colliders and decks of the
objects that differ, the view rays past roofs and crowns once per spot and set of conditioned roofs
and trees near them, and the checks that do not depend on what is there (stairs, waterfalls,
environment areas) run once — the same report as checking every state from scratch
(`reuseStates: false`, which the self-test compares). The camera rules are judged in every state
like the others. Gildhaven with six house flags (64 states) takes about 3 s.

- **Overlaps**: two objects whose conditions can never hold together (`storyExclusive`: a bridge
  `when: bridge-mended` and its flood debris `unless: bridge-mended`) are not reported.
- **Reachability** and everything else that depends on what is there (the walk from the spawn and
  the entrances, exits, villagers, doors, signs, wells, regions, bridges walked end to end, routes,
  blocked doors, the camera rules): a finding that holds in every state where the objects it is
  about are there reads as it always did — something unreachable in every state is the old error
  (when every state was checked). What is **reached only in some states** is one warning per set of
  states, naming them (ground no state reaches stays the old unreachable pocket):

  ```text
  reached only with `bridge-mended`: exit exit_east (→ old-quarry), the walkable ground round
  (44.7, 8.9) — box x 35.5–55.5, z 0.5–17.5 (3737 nodes)
  ```

  Any other finding that holds only in some states names them in brackets ("bridge ford cannot be
  walked end to end: … (without `cleared`)"); several tests read as a condition ("when `mended and
  cleared`", "when `not carpenter-hired or not planks-bought`").
- The info lines: "story states: 4 — what is there depends on `bridge-mended`, `hollis-at-ford`,
  `lantern-found` (every combination checked)", and the walk grid over all states ("… reachable
  from the spawn in some story state, 5270 in all 4").

A single level without a story ignores `when` / `unless` (the game shows everything); its check
does too, and says so in an info line.

```bash
npm run level:check -- --campaign=ferrymans-lantern
```

checks every level file of the campaign — chapter variants included — with `checkLevel` (in its
story states), then the links, the seams and the story (`checkCampaign`; the story files are
`story/<file>` in the campaign folder, listed in `campaign.json`'s `story`):

| Check | Severity |
| --- | --- |
| A listed level, a chapter variant or a listed story file has no file | error |
| A chapter variant whose width or depth differs from its base level's | error |
| An exit leads to an id that is no level of the campaign (or names a variant) | error |
| An exit's entrance is in no file of the target level (in any story state) | error |
| An exit's entrance is missing only in some files of the target (a chapter variant) | warning — info when the exit has a story condition |
| A seam arrival lands on no walkable ground (± 3 tiles) | error |
| `start.entrance` is missing in the start level | error |
| An `at` that is not on whole tiles | warning |
| Overlapping placed levels whose shared tiles differ in walkability or height — for the files of every chapter | warning |
| Touching placed levels whose edge tiles do not match (walkable ↔ not, or > 1 level apart) — every chapter | warning |
| A level no exit chain (or story `travel`) reaches from the start | warning |
| Every level file's `storyIssues` against the story files (an undeclared item, quest or actor, a missing quest stage — in any condition or script — or `call` target, a `travel` to no level, a `done:` of no `once` event of the campaign, a `visited:` of no level) | as the level check, under the file |
| A story script line that does not parse (`story/<file>:<line>`); a `call`, an actor's `talk` or an event's `run` naming no script; a quest stage that does not exist (in a script, a chapter's `when`, an event's `if`, a goal's `done`); a `travel` to no level, or to an entrance in none of its files; a chapter `when`, an event `if` or a goal `done` that does not parse; a reserved word as a chapter's bare `when` (`when: gold`); a chapter `when` that reads `chapter`; a line a background run may not play in the script of a background story event or in any story script a background event's `call`s reach — of a level or a story file, through any number of calls (`story/<file>:<line>`, naming the event) | error |
| The story files' own warnings (bad names, duplicates — an inline `run` / `talk` whose `event.<id>` / `actor.<id>` script exists —, dropped entries, `level` on a `change` event, a `background` that is not true / false); a speaker that is no actor or villager (a `"quoted"` name is meant as written); an actor of the story files no villager of any level is, directed by a story script; an undeclared item or quest in a story script (a `stage:` of an undeclared quest: it has no declared order); a `done:` or `visited:` that names nothing; a `once` / `cycle` key used by scripts of different levels or story files; a start preset naming a missing level, entrance or stage | warning |
| An item taken or checked but given by no script | warning |
| A flag / variable that is read (any condition: `when`, `unless`, `requires`, event and chapter conditions, goals, `if`, `[if]`, `${…}` — not a `\${…}` written as text) but never written (a villager's `flag`, `set` / `clear` / `var`, `campaign.json` `flags`, story `vars`, start presets) | warning |
| The story's reach: an exit that can never open, a level reached only through such exits, a flag set only in levels the player cannot get to | warning |
| A text with no key, or a key or `#line:` tag on no text, in `campaign.json` or a story file (more than three missing keys in a file are summed into one line) | warning — error with `--strict` |
| One key on two texts of `campaign.json` or of a story file (`repeated`) | error |
| One key held with two different Englishes across the campaign's files (`campaign.json`, every level file, chapter variants too, and the story files): a copy edited apart (`npm run i18n:keys -- --fix`, or re-run its generator) | error |
| A flag that is set but never read; declared items, quests, scripts and actors nothing uses; a level without exits (a dead end); arrivals at a player start; each seam's tally; the text keys (keyed texts of `campaign.json` and the story files, and the keys copies in two files share) | info |

**The story's reach** is a fixpoint. It starts at the start level with the campaign's `flags`, the
story's `vars` that start non-zero and every flag a story-file script writes (those run anywhere),
then adds the levels behind exits whose `requires` and `when` could hold and the flags their
villagers and scripts set — a chapter variant once its chapter's `when` could hold — until nothing
changes. A condition could hold unless it needs a flag outside that set (outside a `not`; items,
quests and the clock count as anything), so the check reports only what can never happen.

`--strict` makes `checkLevel`'s composition rules errors, as for single levels. Exit code 1 on any
error; 2 when a level or story file cannot be read or parsed (it is reported, and the rest is still
checked). A generator whose campaign has story files passes `readStory` to `checkCampaign`.

## 10. Making a campaign

1. Make `public/campaigns/<name>/campaign.json` (copy the demo's and edit it) and a `levels/`
   folder; list the levels with their `at` where they should join.
2. Build each level (the editor, or a generator); for a seam, run the road off the map edge at the
   same plane coordinates on both sides, at the same height, with an `exit` over its last tiles
   (no entrance) on both sides.
3. Doors, stairs, interiors: a `use` exit naming an `entrance` in the target, and back.
4. Story: the story files (`story/*.json`: items, quests, actors, start presets; `story/*.story`:
   the actors' talk and the cutscenes), villagers' `actor` / `talk`, `event` objects, exits'
   `requires` / `locked`, `when` / `unless`; chapters with variant files for bigger changes
   ([STORY_SCRIPT.md](STORY_SCRIPT.md)).
5. `npm run level:check -- --campaign=<name>` until clean; play `game.html?campaign=<name>&new=1`
   (`&story=<preset>` to start further on).

[`tools/make-ferrymans-lantern.mjs`](../../tools/make-ferrymans-lantern.mjs) is a compact template:
five small levels from the `LevelFormat` helpers, the campaign file and the story files,
`checkCampaign` before writing, `--check` for byte-identical regeneration.
[`tools/make-emberfall-interiors.mjs`](../../tools/make-emberfall-interiors.mjs) is the template for
rooms: it takes an existing level (Emberfall) as the town, adds the doors, and builds furnished room
levels with a small `roomLevel` / `frontDoor` / `stairLink` toolkit (and a check that no prop's
collider reaches into a wall).

## 11. Limits

See [KNOWN_ISSUES.md](../ai/KNOWN_ISSUES.md#campaigns) (CMP-01 …): only the level behind the
nearest exit is built ahead, and only from 12 u away — a travel that comes sooner (a teleport, a
story script, a dash to the exit) finishes it behind the fader, a travel from anywhere else builds
the level there; the villagers, critters, combat, the maps and the warm-up stay at the travel
(≈ 0.15–0.2 s for the demo's levels, ≈ 0.32 s for a 128 × 128 one); critters start over on each
visit, and a pack fought in part comes back whole (a defeated one stays defeated until a waystone
rest); tiles, heights and water never change (chapter variants);
the editor's checks see every story state at once (its story preview shows one). Levels set aside
around rooms ([§6.3](#rooms-the-levels-set-aside)): never a combat level (a combat level left for
a room, or a combat room, is built at every visit), at most the parent and the last room (a house
with a back door to another outdoor level drops the town), and a level set aside keeps all its GPU
memory meanwhile.
