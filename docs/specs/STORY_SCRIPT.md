## 1. What the story system is

A story is **data**: conditions and short scripts written in level objects and in a campaign's
story files — no JavaScript. It gives a level or a campaign:

- dialogue that follows the story (branches, choices that change things, lines that vary from
  visit to visit, one-time lines);
- **variables** (flags are variables whose value is 1), **items** and **gold**, **quests** with
  named stages and goals, shown in the **journal** (B);
- **events**: scripts that run when the player presses Space somewhere, walks in or out of an
  area, arrives in a level, when a condition becomes true, when the clock passes an hour, when an
  enemy group is defeated;
- **cutscenes**: the camera looks at people and places, villagers and the player walk on the walk
  grid, emote bubbles, fades, a letterbox; hold Esc to skip;
- objects that **come and go while the player watches** (a bridge built during a cutscene, a
  villager who walks off and is gone), and per-level memory (where a villager lives now);
- an **ending**;
- the player's **party**: villagers who join (`party join`), leave, and fight by a rule the story
  sets (`party rule`, `party set`) — [PARTY.md](PARTY.md).

The runtime exists only where there is a story: a campaign, or a single level with an `event`
object or a villager with a talk script or an actor (`levelHasStory`). Every other level plays
exactly as before — no story module, DOM, key binding or per-frame work, the same programs and
fingerprints.

## 2. Where the story lives

| What | Where | Notes |
| --- | --- | --- |
| Conditions on any object | `when` / `unless` (every type; no default, absent from files that do not use them) | §3; applied live on the `LIVE_STORY_TYPES`, on entering for the rest (§9.5) |
| What a villager says | npc `talk` (a script, `string[]`) | replaces `dialogue` / `action` / `script` when it holds a line |
| Who a villager is across levels | npc `actor` | the actor's talk script (story files), one visit count, its name as a speaker |
| What happens somewhere / sometime | `event` objects (a rectangle: `on`, `run`, `label`, `if`, `once`, `at`, `group`) | §6 |
| Named spots for staging | `marker` objects (`name`, `facing`) | `walk ilse well-side`, `camera well-side` |
| Exits' conditions | exit `requires` (a condition) | [CAMPAIGN_FORMAT.md §4](CAMPAIGN_FORMAT.md#4-exits-and-entrances) |
| Chapters | campaign.json chapter `when` (a condition) | [CAMPAIGN_FORMAT.md §5](CAMPAIGN_FORMAT.md#5-story-flags-conditions-chapters) |
| What the whole story shares | story files `story/*.json` and `story/*.story`, listed in campaign.json `story` | §8: variables, items, quests, actors, scripts, campaign events, start presets |

A villager's `flag` (set when a conversation ends) still works; it is a shorthand for `set` at
the end of a talk script.

## 3. Conditions

A condition is a short expression; nothing is evaluated as code.

```
bridge-mended                          a flag (a variable that is not 0)
not refused and item:plank >= 3        items you carry
met = true                             true / false are 1 / 0
quest:find-ilse = active               a quest's state: none | active | done | failed
stage:find-ilse >= found-chart         a quest's stage, compared by the order of its declared stages
deliveries >= 3                        a variable
gold >= inn.price                      a number compared with a variable
hour >= 20 or hour < 6                 the time of day (0–24)
day > 2                                the day (1 on a new game, +1 at every midnight)
visits:hollis >= 1                     conversations with an actor / villager
visited:old-quarry                     the levels entered (campaigns)
done:ev_ford                           this level's `once` event (or a story event, a `once` block) has run
done:mill-road.ev_gate                 another level's `once` event has run
chapter = lanterns-home                the chapter in force (campaigns)
level = millbrook · weather = rain     the level (base id) · the weather (in a room, the one outside)
visits                                 (in a talk script) conversations with this villager before this one
party >= 2                             how many members the player's party has (0–3)
party:sela                             that villager (its id, actor or name, in any case) is in the party
```

```
expr  := or ; or := and ('or' | '||') and … ; and := not ('and' | '&&') not … ; not := ('not' | '!') not | atom
atom  := '(' expr ')' | 'true' | 'false' | ref [ ('=' | '==' | '!=' | '<' | '<=' | '>' | '>=') value ]
ref   := name | kind ':' name | hour | day | gold | chapter | level | weather | visits | party
kind  := item | quest | stage | visits | visited | done | party
value := number | 'true' | 'false' | name
number := plain decimals: 3, -2, 0.5, .5  (no exponent: 1e3 is neither a number nor a name)
name  := letters, digits, _ . -  (not a number)
```

- A reference standing alone is true when it is not 0 / '' / `none` (`quest:x` alone: started);
  `true` / `false` alone are constants. Words (`and`, `true`, `gold` …) are read in any case.
- **The right of a comparison.** Text references (`quest:`, `chapter`, `level`, `weather`) compare
  only with `=` / `!=` to a word; a quest compares only with its four states. A stage reference
  compares with a **stage name** (or a number). Every other reference compares with a number,
  `true` / `false` (1 / 0: `met = true`) or a **variable name** (`gold >= inn.price`); a reserved
  word or a game value there is an error (`gold >= day` — two game values cannot be compared).
- **Stages.** `stage:<quest>` is the number of the quest's current stage — its place among the
  stages the story files declare for it, else among the stages the quest reached, in order; 0
  before the first. A stage name on the right counts the same way; one the quest neither declares
  nor reached reads as one past every stage reached, so `stage:q >= x` holds only once `x` is
  reached. The checks report a stage that a declared quest does not have (an error — in every
  condition and script) and a `stage:` of a quest the story files do not declare (a warning: its
  stages have no declared order).
- **`done:` keys.** A `once` event is remembered as `<level>.<id>` (the base level id; on a single
  level its file name), a story-file event as `story.<id>`, a `once` block by its key.
  `done:<id>` reads this level's event `<id>`, a story-file event `<id>` or a `once` block `<id>`;
  `done:<level>.<id>` another level's event. Only `once` events are remembered: `done:` of an
  event without `once` never holds (the checks warn, and when a key names nothing). `once`, `cycle`,
  `seq` and `pick` keys are **global**: two scripts that use one key share it — the block runs once
  for both, the turns are counted together (the checks warn; one actor's villagers count as one).
- **`visited:<level>`** reads a base level id of the campaign (the checks warn about any other);
  on a single level it never holds.
- **Reserved words** — `hour day gold chapter level weather visits party and or not true false
  ending self random player time none` — cannot be flag names in a condition (`set gold` is an
  error). `party` was kept for later until it became a game value (the number of members); alone
  in a `when` / `unless` (the flag rule below) it is still a flag that can never be set — an error
  with the hint (`party > 0`, `party:<who>`).
- **`party:<who>`** is 1 while that villager is a member of the player's party, else 0 — by its
  id, its story actor or its name, in any case (a name with spaces cannot be written here: use the
  id or the actor). A member joined in one level is a member in every level
  ([PARTY.md §7.2](PARTY.md#72-conditions)).
- **Two rules for a bare name.** The fields written before conditions existed — `when`, `unless`,
  an exit's `requires`, a chapter's `when` — keep the **flag rule**: one bare name is always that
  flag, and a value that does not parse is read as one literal flag name (`level:check` and the
  editor's *Check for problems* report it as an error with the fix). A reserved word there
  (`when: gold`, `when: day`) would be a flag that can never be set: an error, with a hint (write
  `gold > 0`). Every other condition — an event's `if`, a campaign event's `if`, a quest goal's
  `done`, a script's `if` / `elif` / `[if …]` — is read as scripts write it: `if: gold` reads the
  purse.

## 4. Scripts

A script is a list of lines — `string[]` in a level or story JSON file (the author's text
verbatim), or a section of a `.story` file. One command per line; blocks by indentation (any
deeper indentation opens the block; a tab counts as 2 spaces — a script that indents with tabs
and with spaces says so with its indentation errors). Lines indented under a line that takes no
block (dialogue, a plain command) are reported and left out; the line itself stays.

```
if bridge-mended
  Hollis: She'll hold. Off you go.
  stop
Hollis: Wren sent you? Bring me three {oak planks}.
- You have ${item:plank} so far.
choice Give Hollis the planks?
  > Not yet
    - The river won't wait forever.
  > [if item:plank >= 3] Here they are
    take plank 3
    set bridge-mended
```

**What a line is** — decided from its first characters, top to bottom:

| Line | Meaning |
| --- | --- |
| `# …` | a comment (only as the first character after the indentation) |
| `> label` / `> [if c] label` / `> [once] label` / `> [once if c] label` | an option of a `choice` (`once` / `if` in any case; `[if]` without a condition is an error; any other `[…]` stays in the label: `> [Lie] I never saw her`) |
| `* line` / `*` + indented lines | an alternative of a `cycle` / `seq` / `pick` |
| `: text` | the narrator (no name plate) |
| `- text` | the speaker of the nearest line of dialogue **above it in the text** (in a talk script with none above: the villager talked to) |
| `word …` where `word` is a command (lower case, then a space or the end) | a command (§5): `toast Obtained: an apple` is a command |
| `Name: text` / `"A voice": text` | a line of dialogue; the name is everything before the first colon (≤ 60 characters), or quoted — a space must follow the colon (`Hollis:Hi` is an error that says so) |
| anything else | an **error** — a misspelt command never turns into dialogue ("did you mean …?") |

**Speakers.** A name that is a villager of the level (id, actor or name, case-insensitive) or an
actor of the story files shows that character's name plate and colour; any other name is shown as
written (`level:check` warns unless it is quoted).

**Text.** `{word}` is gold (as in plain dialogue); `${ref}` is a value — `${gold}`,
`${item:plank}`, `${deliveries}`, `${hour}` (spaces inside the braces are ignored: `${ gold }`);
`${stage:find-ilse}` shows the stage reached (its id, not its number), `${quest:find-ilse}` the
quest's state. `${` always begins a value, so a `$` just before it is a dollar sign
(`$${price}` → `$12`); `$$` anywhere else is one dollar sign (`$$5` → `$5`); a reference that
does not parse stays as written. **A backslash before a `$` writes that `$` as it is**:
`\${gold}` shows `${gold}`, `\$` a dollar sign (`\$${gold}` → `$12`); two backslashes there are
one backslash (`\\${gold}` → `\12`). `\n` is a line break and `\\` a backslash; any other
backslash stays as written. This holds for every text a script shows — dialogue, a `choice`'s
question and its options, `toast`, `banner`, `bark`, a quest's title and stage text, the
ending's title — and for the texts of the story files (quest goals, stage texts), where `\$` and
`\\$` work the same (a JSON string writes the backslash as `\\`) and a line break is JSON's own
`\n`.

| Written | Shown (`gold` = 12) |
| --- | --- |
| `${gold}` · `$${gold}` · `$$5` | `12` · `$12` · `$5` |
| `\${gold}` · `\$5` · `\$${gold}` | `${gold}` · `$5` · `$12` |
| `\\${gold}` · `\\\${gold}` | `\12` · `\${gold}` |

**Windows.** Consecutive lines of dialogue — and commands that take no time between them (`set`,
`give`, `sfx` …) — are one dialog window; a `choice` after lines shows its options on the last
line (or its own question). That holds across a block too: a `choice` right after an `if` /
`else`, a `cycle` … whose last line is still in the window (the player has read it) puts its
options on that line — the same speaker and text, shown whole at once, not typed again
(`DialogBox.heldLine`). A `choice` **with its own question** after a held line of the same
speaker puts the question under that speech in the same window (`DialogLine.ask`, added
2026-10-10: the speech stays, only the question types, the options open above the window) instead
of a page of its own. A `choice` with no line before it in the window (the script's first, or
after a command that closed it) is a page of its own, its options under an empty text — give it a
question. Commands that take time (`wait`, `walk`, `camera`, `fade`, `travel` …) close the window
first.

**Blocks.**

| Block | Runs |
| --- | --- |
| `if c` · `elif c` · `else` | the first block whose condition holds |
| `choice [question]` | the picked option's block; options with `[if c]` are offered while `c` holds, `[once]` options go away once picked (≤ 8 options) |
| `loop` … `break` | the block again and again until `break` or `stop` (at most 500 times) |
| `once <key>` | the block the first time only (the key is saved) |
| `cycle <key>` | one `*` alternative each time, in turn, round and round (an alternative with an error stays in its place, empty: the others keep their turns) |
| `seq <key>` | one alternative each time, then the last one again and again |
| `pick <key>` | one alternative **at random, per journey**: chosen by the key, the day, the count and the journey's own seed (a new journey draws one; the save keeps it), so two journeys pick differently, and a reload replays the same pick — runs are atomic (§9.3), the run starts again from the same state |

Limits: 4 000 lines a script, blocks 16 deep, 2 000 characters a line, 20 000 commands per run,
`call` 8 deep. A line with an error is left out (the rest runs) and reported with its number.

**Translation keys.** Every line that shows a text a player reads carries its text key as a
trailing tag, `#line:<GUID>` ([I18N.md §4.2](I18N.md#42-keys-and-lookup)): a line of dialogue, a
`choice`'s question and each option, a `bark`, a `toast`, a `banner` (its title has the tag's
key, its subtitle `<GUID>.2`), a `quest … stage` text and the ending's title — when the text is
not blank (`holdsText`). This holds for a level's `talk` and `run` scripts and for a story
file's scripts, inline or in a `.story` file; a script run by `call` keeps its own keys.

```
- Ah, a traveller. Millbrook has a favour to ask of you. #line:4E7803B69703EBCB43224D1BE7F09492
choice Would you look for her? #line:0957D2029292F960DA799BE00CF9D990
  > I will find her #line:78D0E5170EAF6CC458AFD37C90C29DBF
    quest find-ilse stage asked
```

- The tag is cut off before the line is read, so no text, label, speaker or `[once]` key holds it.
  A tag of lower-case digits is read, and written, in upper case.
- A `#line:` still in a line after its tag is cut (a malformed tag, a second tag) is an error of
  that line. A line therefore cannot hold the words `#line:` themselves.
- A **parked** line — a comment, a line with an error or a line its error left out, a line past a
  limit — keeps its tag for when it reads again, and is never given a new one. A tag on a line that
  shows no text (an `if`, a `set`, a blank line) is stray: it is ignored, and the checks report
  it.
- A `.story` file's `== id` header carries no tag. A tagged header is no header (its line joins
  the script before), so retagging drops the tag, and the checks warn about it.
- The editor and the generators keep the tags through every edit: an edited line keeps its key, an
  inserted line gets a new one, and a moved line keeps its own, so its translation follows it
  ([I18N.md §4.10](I18N.md#410-keys-through-edits-the-editor-the-generators-the-tools)). The
  editor shows and compares scripts without their tags. Never write a tag by hand:
  `npm run i18n:keys -- --assign` keys a line typed into a file.
- A speaker and a `quest … start` title are names (terms), not keyed. Lines run with
  `__game.story.run` have no keys: they stay English in every language and record a `nokey` miss
  each (nothing is translated by its English, I18N.md §4.2).

## 5. Commands

`<who>` is `player` or a villager of the level the script runs in — its id, actor or name, in any
case; a name with spaces in quotes (`walk "Elder Wren" well`). A member of the player's party is
found first: `bark`, `emote`, `face`, `walk`, `teleport`, `camera` and `wait` direct the member
(its villager is hidden while it is in the party; `home` changes nothing for it). An actor of the
story files that no villager of that level is cannot be directed: `walk`, `teleport`, `face`,
`home` and `camera` end the run there, `emote`, `bark` and `wait` do nothing (the checks warn). `<place>` is a villager, a
marker (name or id), an entrance (name) or any object id (its position or centre) — quoted when its
name has spaces.

| Group | Command | Does |
| --- | --- | --- |
| flow | `stop` · `break` · `call <script>` · `wait <seconds>` · `wait <who>` | end the script · leave a loop · run a story-file script (one name, nothing after it) · pause · wait for a `nowait` walk |
| state | `set <flag>` · `clear <flag>` · `var <name> = / + / - <n>` | flags and variables |
| | `give <item> [n]` · `take <item> [n]` | items (`gold` is money); a toast says what changed hands |
| | `quest <id> start [title]` · `quest <id> stage <stage> [text]` · `quest <id> done` · `quest <id> fail` | quests (the journal; toasts "New quest", "Quest updated" …); the title may use `${…}`, but it is a name, translated as a term: a title or a stage text with values is saved filled in and stays English (write them without values, I18N.md §4.5); a stage given to a finished or failed quest opens it again |
| world | `home <who> [x z]` | where a villager lives from now on (saved per level) |
| | `time <h>` / `time <hh:mm>` · `weather clear / rain / snow` | the campaign's clock moves **forward** to that hour (0–24; minutes 00–59; inside a level with its own hour: the hour outside) — the day turns when it passes midnight and the `time` events between run, also for a jump of 12 hours or more · the weather (in a room — `environment.interior` — it changes outside: none shows in the room) |
| | `travel <level> [entrance]` | campaigns: go to another level of the campaign — the script goes on there (a level the campaign does not list ends the run) |
| | `rest` · `heal` · `shop` · `builtin <conversation>` | sleep until morning · combat levels: full health (the party's members too) · the villager's built-in shop · a hand-written conversation (dialogue.js) |
| | `ending <id> [title]` | the end card (the title may use `${…}`), then the title screen (the save keeps the ending) |
| staging | `cutscene` | letterbox, no HUD, skippable (hold Esc) until the script ends |
| | `walk <who> <x> <z>` / `walk <who> <place>` `[run] [nowait]` | along the walk grid; waits unless `nowait`; stuck 3 s → put at the goal |
| | `face <who> up / down / left / right / <place>` · `teleport <who> <x> <z> / <place> [facing]` | turn (towards an actor, marker, entrance or object) · put somewhere |
| | `emote <who> ! ? ... note heart zzz anger sweat idea [seconds]` | a bubble over the actor |
| | `bark <who> <text>` | a short speech bubble over the actor (`bark hollis Mind the ford!`, `bark "Elder Wren" ${gold} gold? Hm.`): the text is the rest of the line, with `${…}` and `{word}` as in dialogue; it holds no one and opens no dialog window — the line a background event says (§6), and it works in any script; how long it shows is the game's (no seconds) |
| | `camera <who> [s]` · `camera <x> <z> [s]` · `camera <place> [s]` · `camera reset [s]` · `shake [amount]` | the camera looks there (follows an actor) until `camera reset` or the end of the script |
| | `fade out [s]` · `fade in [s]` | to black and back |
| party | `party join <who> [as <class>] [<preset>]` | a villager of this level joins the player's party (at most 3) — as a class (`warden`, `ranger`, `mystic`; else by the weapon it carries) and with a preset rule (`balanced` — the default —, `aggressive`, `guardian`, `support`, `hunter`, `passive`; the two in any order): `party join sela as warden guardian`. Its villager is hidden; the member walks with the player from level to level |
| | `party leave <who>` · `party rule <who> <preset>` · `party set <who> <field> <value>` | a member leaves (its villager is back where the member stood) · its combat rule becomes the preset's · one field of its rule changes (`party set sela heal often`; the fields and their values: [PARTY.md §3](PARTY.md#3-rules-presets-classes)) — a toast names the rule (quiet while a cutscene is skipped) |
| | `party menu [<who>]` | the tactics panel (on that member) — the script waits until the player closes it |
| feedback | `banner <title> [\| subtitle]` · `toast <text>` · `sfx <sound>` · `music <track> / on / off` | |

The party commands never stop a run: a full party, a villager who is not here (or not there as
the story stands) or a member already, a member who is not one — a warning in the console, and the
script goes on. A class, preset, field or value that does not exist is a parse error that lists
them and offers the closest when it is near — one edit for a word of up to 4 letters, two for a
longer one, two letters swapped count as one (`party set sela hael often` → `"hael" is not a field
of the rule (target, distance, …) — did you mean "heal"?`) — or a value a word means (`party set
sela distance near` → `close`, `evade no` → `off`); a name of the list in quotes says to write it
without them (`party join sela as "warden"`), a preset after `as` or a class given to `rule` says
which it is (`party rule sela warden` → the class is chosen when it joins: `party join sela as
warden`); `party join player` is an error too (the player leads the party). Only a `party join`
that happens makes the party (a game nobody joins loads none of it: a refused join makes none);
the other commands do nothing without one.

Objects come and go only through **flags and conditions** (`set bridge-built` and the bridge's
`when: bridge-built`) — there is no `show` / `hide`. Coordinates a script names (`walk`, `teleport`,
`home`, `camera`) are kept within 2 units of the map; a facing is one of the four (an unknown one —
on a marker or an entrance too — is not used).

## 6. Events and triggers

An `event` object is a rectangle with a trigger (`on`), a script (`run`) and optionally a Space
prompt (`label`, default "Look"), a condition (`if` — read as scripts write it: `if: gold` reads
the purse, §3), `once`, `background` (below), an hour (`at`) or an enemy group (`group`). Its own
`when` / `unless` apply as on any object (an absent event never runs).

| `on` | Runs when | Notes |
| --- | --- | --- |
| `use` | Space inside its rectangle | a prompt like a door's; preferred over another prompt at the same spot; offered only while `if` holds |
| `enter` / `leave` | the player walks in / out | not on arrival inside it (like walk exits), nor when a run moves the player (a walk, a teleport): where the player stands when it ends counts |
| `arrive` | the player arrives in the level | after a travel's fade-in and at the start of play (a new journey, a single level) — not on Continue: the game was saved after the arrival; the event runs that were queued or going on then run again instead (§9.3) |
| `change` | its `if` becomes true | the value on entering counts as the previous one: no run on entering while it already holds (use `arrive` + `if` for that); conditions are read again when the story changes, every tenth of an hour, and when the weather or the gold changes |
| `time` | the clock passes the hour `at` going forward | the campaign's clock (going into or out of a level with its own hour is no jump); time passing and jumps forward of less than 12 hours count (the T key), the `time` command always; the game setting the clock (Continue, a new journey) does not; a `rest` skips them |
| `cleared` | the last foe of enemy group `group` falls | combat levels; again after a waystone respawn unless `once`; never for a group the story has away (its foes cannot fall) nor on entering a level where a campaign remembers the group defeated (its foes are simply not there: CAMPAIGN_FORMAT.md §6.4) |

`once`: never again after it ran (saved: `<level>.<id>`; `done:<id>` reads it in its level,
`done:<level>.<id>` anywhere — §3). The story files' **campaign events** have `on: change`
(anywhere) or `on: arrive` (optionally in one `level`; `level` on a `change` event is ignored,
with a warning); a `once` one is saved as `story.<id>`; `background` works as on a level event.

**Background events.** `background: true` (an `event` object's *Runs in the background*, a story
file event's `"background": true`; absent or anything else: false) makes the event's run a
**background run**: it plays while the player keeps walking — it holds no one and never opens the
dialog window. So it may use only what needs no input and moves no one but villagers
(`BACKGROUND_OPS` in [StoryScript.js](../../src/engine/level/StoryScript.js)):

```
# a background event (on: enter, background: true) — the player walks on while it plays
bark hollis Mind the ford, traveller!
walk wren well-side nowait
cycle market-gossip
  * bark wren They say the miller's lantern went out.
  * bark wren Rain by evening, mark me.
emote hollis note
```

| May | Command |
| --- | --- |
| yes | `bark` · `emote` · `walk` / `face` / `teleport` (villagers and party members only — never `player`) · `home` · `wait` · `set` · `clear` · `var` · `give` · `take` · `quest` · `heal` · `party join` / `leave` / `rule` / `set` · `sfx` · `toast` · `banner` · `music` · `weather` · `shake` · `call` · `stop` · `break`; the blocks `if` / `elif` / `else`, `loop`, `once`, `cycle` / `seq` / `pick` (their lines follow the same rule) |
| no | dialogue (`Name: text`, `: text`, `- text` — write a `bark`) and `choice` (they need the player) · `cutscene`, `camera`, `fade` (the screen and the camera stay the player's) · `travel`, `rest`, `shop`, `builtin`, `ending` (they hold or move the player) · `time` (a clock jump re-lights the scene and runs the `time` events between at once — a scene change, for a run that holds the player) · `party menu` (the tactics panel needs the player) |

`banner`, `music`, `weather` and `shake` are allowed: they need no input and move no one (the
region banner, the music and the weather change while the player walks anyway; a shake jolts the
camera without taking it, as a hit in combat does). `level:check` (and the editor's *Check for
problems*) reports each line of a background event's script that may not run there as an error
("cannot run in the background: dialogue needs the player — drop "background" or use "bark"");
the campaign check also follows the `call`s of background events — level events and story file
events — into the story files' scripts. A script reached through `call` is checked again as it
runs: the game asks before each line of a background run, and a line that may not run there ends
the run with an error.

Events of a level that are queued but have not run when the player leaves it are dropped (story-file
events go on). An event that keeps setting itself off — two `change` events that undo each other —
is held back after 8 runs in 2 seconds, with a warning.

## 7. Talk scripts and actors

A villager with a `talk` script says that; else, with an `actor`, the actor's talk script from the
story files; else its plain `dialogue` / `action` / `script` as before. Conversations count as
**visits** — keyed by the actor, else `<level>/<villager id>` in a campaign (the bare id on a single
level) — readable as `visits` (this villager, in its talk script) and `visits:<actor or id>`.
A conversation is counted when it ends: inside it, `visits` and `visits:<who>` read the count before
it (a reload in the middle counts nothing). `visits:<actor>` reads the actor's count in any level,
also where no villager is that actor. Several villager objects with one `actor` (the same character
in several levels and chapter variants) share the talk script and the count.

A **party member** talks with its villager's script (`StoryRunner.talkFor`): the `talk` of its
villager's object when that object is on this level (by id; its actor's when it has none), else
its actor's talk script from the story files — else the party's own conversation (tactics, part
ways). Its conversations count as its villager's: under its actor, else `<the level it joined
in>/<id>`. A talk script that serves both can ask `if party:<who>` (the demo's companions on
Cinderwatch Pass — Sister Ilse, Rook and Sela —, whose talk scripts also answer a full party with
`if party >= 3`: [PARTY.md §9](PARTY.md#9-the-demo-the-companions-of-cinderwatch-pass)).

## 8. Story files

campaign.json lists them: `"story": ["main.json", "dialogue.story"]` (files in the campaign's
`story/` folder; names `a–z 0–9 -`, then `.json` or `.story`; at most 64 — the rest is ignored,
with a warning). They are merged in that order; a name declared twice keeps the first (a warning)
— also an event's inline `run` or an actor's inline `talk`, which are the scripts `event.<id>` and
`actor.<id>`: a `== event.<id>` script read before keeps its lines.

**`<name>.json`** (`format: "luminati-story"`, `version: 1`) — every section optional:

```json
{
  "format": "luminati-story", "version": 1,
  "vars": { "deliveries": 0 },
  "items": { "plank": { "name": "Oak Plank", "text": "A sound oak plank.", "textKeys": { "text": "F7A3…" } },
             "ferry-lantern": { "name": "Ferry Lantern", "key": true } },
  "quests": { "find-ilse": { "title": "The Missing Ferryman", "text": "…",
    "stages": [ { "id": "asked", "text": "…" }, { "id": "found", "text": "…" } ],
    "goals": [ { "text": "Oak planks (${item:plank} of 3)", "done": "item:plank >= 3" } ],
    "textKeys": { "text": "890B…", "stages": { "asked": "6E2B…", "found": "376F…" }, "goals": ["6C30…"] } } },
  "actors": { "hollis": { "name": "Hollis", "preset": "farmer", "portraitColor": "#b07b44", "talk": "hollis" } },
  "scripts": { "small-reward": ["give gold 20", "sfx chime"] },
  "events": [ { "id": "ford-open", "on": "change", "if": "bridge-mended", "once": true, "run": ["toast The way east lies open. #line:9B0C…"] },
              { "id": "gossip", "on": "arrive", "level": "millbrook", "background": true, "run": ["bark wren Back again? #line:5D21…"] } ],
  "starts": { "chapter-two": { "level": "old-quarry", "vars": { "bridge-mended": 1 }, "items": { "cellar-key": 1 },
    "quests": { "find-ilse": "bridge" }, "gold": 0 } }
}
```

- `vars`: declared names and their values on a new game (`true` = 1).
- `items`: display name, journal text, `key` (a key item, listed apart). `gold` is built in.
- `quests`: title, text, named `stages` (their order is what `stage:x >= y` compares), `goals`
  (ticked in the journal while `done` holds — a condition as scripts write it: `done: gold >= 10`
  reads the purse).
- `actors`: name, look, name-plate colour, `talk` (a script id, or the lines inline: the script
  `actor.<id>`).
- `scripts`: named scripts (`call`, actors' `talk`, events' `run`).
- `events`: `id`, `on` (`change` | `arrive`), `if` (a condition as scripts write it), `once`,
  `level` (arrive only), `run` (a script id, or the lines inline: the script `event.<id>`),
  `background` (`true`: a background run, §6 — its script and the scripts its `call`s reach may
  use only what a background run may; a value other than `true` / `false` is warned and read as
  false).
- `starts`: debug start presets for a new game (`game.html?campaign=<c>&new=1&story=<preset>`):
  where it begins and what it already has (quests: the stage reached, or `done` / `failed`).
- `textKeys` (an item, a quest): the text keys of its texts
  ([I18N.md §4.2](I18N.md#42-keys-and-lookup)). An item's is `{ "text": key }`; a quest's is
  `{ "text": key, "stages": { <stage id>: key }, "goals": [key, …] }`, its stages by the loader's
  stage id (`stageIdOf`: an entry's `id`, else its place counted from 1) and its goals by their
  raw index. `buildStory` puts each key on the built item, quest, stage and goal (`textKey`). The
  lines of `scripts`, actors' `talk` and events' `run` carry `#line:` tags (§4); an event is
  matched by the loader's id (`eventIdOf`: its `id`, else `event-<n>`). `eventIdOf` and
  `stageIdOf` live in `src/engine/level/StoryCondition.js` (re-exported by StoryScript.js and
  StoryFormat.js), so the engine's text keys read ids the way the loader does.

**`<name>.story`** — scripts as plain text, each after a `== <script id>` line:

```
== hollis
if bridge-mended
  - She'll hold. #line:797D…
  stop
- Bring me three {oak planks}. #line:A41C…

== ford-scene
cutscene
camera hollis 1.2
…
```

Generators write them with `serializeStory` / `serializeStoryText` (StoryFormat.js).

## 9. In the game

### 9.1 Runs

A script runs as a **run**: one at a time; the player is held (`game.busy`), combat waits.
Events queue while another run, a conversation, the map, the journal or the party's tactics panel
holds the player, and run in order when it is free. A run goes on across a `travel` (actors are looked up for every command).
A failing command ends the run with a warning (in a development build also a red toast); the
window, the camera, the letterbox, the villagers and the screen (a run that stopped after
`fade out`) are always given back. On a `travel` the camera goes back to the game; a later `camera`
in the run starts from the new level.

**The background lane.** An event with `background: true` runs beside play instead: the player
keeps walking, nobody is held, no window opens. Its script uses what needs no input — `bark` lines
over villagers, emotes, villagers walking and turning, state changes, sounds, toasts (§5 lists them;
a dialogue line, a choice, the camera, the player … end the run with an error, and the checks report
them first). Up to 8 background runs play at once (the same event never twice); while the player
is held (a run, a conversation, the map, the journal, the tactics panel, a travel) they wait — no line runs, walks
and waits stand still, walkers stand idle — and go on after. A villager a background run directs
goes to the main lane as soon as a run there directs it or waits for it (`wait <who>`): that
background run stops where it is; a background run never takes a villager the main lane directs. A
`nowait` walk still going when a background script ends goes on to its goal (the villager is its
own again there). Background runs are not atomic (their changes are saved as they happen); a `once`
one cut by a reload runs again from its start on Continue (what it changed before stays), the
others do not; they stop when the player leaves the level, and a new journey ends them. `<who>` is
the player in any case (`Player`).

### 9.2 Staging

![The ford cutscene: letterbox, the camera on Hollis](../assets/screenshots/ferrymans-lantern-ford-cutscene.jpg)

The `camera` command directs the camera (its look-ahead off, the map bounds widened, the shadow
frustum and the depth of field on what it looks at); `camera reset` (or the end of the run) hands
it back. Walks use the level's walk grid (`combat/Nav.js`; a combat level's own) — directed
villagers stop their own behaviour until the run ends (`home` keeps them where they are). A long
way across a big map is searched again over the whole map when the level's search budget runs out,
and walked in legs when the path the search keeps ends short of the goal; only a goal with no way
to it is walked straight (a warning) and reached by the 3-second fallback. The grid knows its
connected parts, so a goal with no way is known at once (no search); on a level without combat
whose scripts (its events, its villagers', the story files') hold a `walk`, the story's grid is
built ahead in idle time after arrival — on a combat level only when the combat grid finds no
way.
`cutscene` adds the letterbox and lets the player skip: holding Esc for 0.6 s runs the rest at once
(waits end, walks arrive, the camera snaps, lines without a choice are skipped; a choice is still
asked; every state change still happens). The lines skipped record no content misses (I18N.md
§4.2): only the page that asks is looked up as shown, and a skipped `give` / `take` shows no toast.

### 9.3 State and saves

The story's values (`StoryState`): variables, items (with the names a shop gave the items no story
file declares, `itemNames`), gold, quests (state, stage, stages reached; a script's own title and
stage texts, in English, each stage text with its content key and its English before the values,
`keys` / `src`: I18N.md §4.5), the `once` keys, the turns of `cycle` / `seq` / `pick`, visit
counts, the day, per-level homes, the ending. A campaign saves them in its save (`story`, save version 2; an older save is not read —
[CAMPAIGN_FORMAT.md §7](CAMPAIGN_FORMAT.md#7-saved-games)). **Runs are atomic**: a save taken while a
run goes on writes the game as it was when the run began, so a reload replays an event, never half
of it; `once` is recorded when the run ends. The event runs queued or going on when the game is
saved are saved with it (`story.pending`) and run again on Continue, so a `change` or `enter` event
interrupted by a reload is not lost; a conversation that was going on starts again with the same
villager (its visit counts when it ends). Each journey has a **seed** (`story.seed`, random on a new
journey; `&seed=<n>` in the URL pins it for tests, `__game.story.seed`) that `pick` mixes in: two
journeys pick differently, one journey picks the same after a reload (a story without a seed, 0,
picks the fixed way). Flags of the older free
form — campaign.json `flags`, a villager's `flag` (any short text: `met hollis`) — are kept as
written. Keys longer than 200 characters (a long `[once]` label) are shortened with a
hash, so they survive a save. On a single level the story lives for the session. On a combat level
the purse is the combat's; it goes back to the story when the player leaves.

### 9.4 The journal

**B** opens the journal (a story only): the quests (active first; their stages reached, goals
ticked) and the items (key items apart) and gold. B or Esc closes it; it holds the player like the
world map.

It shows everything in the page's language (I18N.md §4.5, §4.8): the quest titles and item names
as terms; the story files' quest and item texts, stages and goals by the keys the story files hold
(the built `textKey`, from the quest's and item's `textKeys`), their values filled in after; a stage text a script gave by the key saved with it while the saved text is its
English (one saved with values filled in shows as saved, in English; one saved without a key
shows as saved, in English, a `nokey` miss). An item is named by the story file's name, else the
name a shop gave it by, else its id in title case.

### 9.5 Objects that come and go

![The same view after `set bridge-mended`: the bridge built, the flood debris and the notice gone](../assets/screenshots/ferrymans-lantern-bridge-built.jpg)

When the story changes, the game re-checks every `when` / `unless`:

- **live** (`LIVE_STORY_TYPES`): villagers (shown / hidden, their colliders parked, not
  talkable, off the minimap), exits, entrances, events, markers, regions, critters, particle areas
  and every prop but the combat ones — house, windmill, well, market stall, tree, rock, haystack,
  bench, barrel, crate, crate stack, flower box, signpost, fence, bridge, waterfall, lamppost, wall
  torch, campfire, point light, and the interior furniture (bed, table, chair, shelf, hearth,
  counter, rug, staircase, wardrobe, wall window, grain sacks — a hearth's fire and light come and
  go with it). Props (and particle areas) with the same `when` / `unless` pair
  are built as one **story group**, merged into the level's own batches like any other prop (the
  same draw calls as without the condition; on a big level its shadow proxies too), where the
  group owns vertex ranges; a group that comes or goes shows / hides its meshes — its ranges
  collapsed onto one point (nothing drawn, no shadow, no glowing window) or restored, only those
  vertices uploaded, what stays outside the batches hidden or shown: flames and glows, a
  windmill's sails (which stand still while it is absent), a waterfall's sheet and foam pool
  ([GAME.md §4.9](../architecture/GAME.md#49-live-story-groups-in-the-levels-batches)) —, adds /
  removes its colliders and walk surfaces (whoever stands on ground that went away, or where a
  house came, is moved to standable ground; the shore re-bakes around the colliders standing in
  water — a bridge's posts —, on a big level in a worker), its prompts (a house's door, a well, a
  sign), map markers, particles (chimney smoke, embers, waterfall mist, the particle areas), its
  campfires' crackle and its waterfalls' roar and spray; its lamps (a house's door lantern) fade
  through the light pool (`LightPool.setHidden`: no light is created or removed); the maps are
  painted again when a type they show changed (a house, a windmill, a well, a bridge, a tree …:
  `LEVEL_MAP_TYPES`). A critters group that is absent has its animals hidden and standing still,
  and villagers chase none of its chickens; when it comes back its animals start again at their
  start points.
- **What stays**: the ground. Tiles, heights and the water never change (chapter variants for
  that): the water a waterfall falls between keeps its two levels and the step face between
  them, and its shore; under a house, a windmill or a well that is absent no grass grows (the
  foliage is scattered once, around every story prop's colliders), and the bushes along a
  house's walls stay. Villagers standing where a house came are sent home, as for any prop;
  critters are not moved.
- **live, combat** (`enemy`, `chest`, `waystone`, also `LIVE_STORY_TYPES`): a combat level loads
  every enemy group, chest and waystone, present or not — their kinds' sheets painted, their
  sprites and props built and warmed at load, so nothing compiles when one comes — and the combat
  system keeps the absent ones out of play (`GlaiveCombat.applyPresence`, called by the story's
  presence after the world's). An absent **enemy group** has no AI, is not drawn, not hit, not on
  the minimap, not counted for its `cleared` event (`state().combat.enemies.absent` counts it);
  its boss's arena closes nothing (no exclusion, the enemies' walk grid opens there, no map
  marker). A group the story takes away goes silently, also mid-fight: the lock-on and the aggro
  drop, its tokens, markers and projectiles go, its boss's fight ends (the gate opens, the adds
  go, the bar hides). A group that comes spawns at its home — no reward replayed; its foes that
  had fallen stay fallen, and a waystone rest brings those back as usual, present or not.
  **Chests and waystones** are story groups like the props above (their prop, collider, prompt,
  painted map and marker come and go); an absent chest is not discovered or opened (an opened
  chest that comes back still offers nothing), an absent waystone is not attuned or rested at,
  and the checkpoint it held falls back to the level's start. A campaign keeps every enemy group
  in the level it builds, so a level whose enemies are all away at first still plays with combat.
- **on entering**: since 2026-10-07 no type — every type of the catalog is live. A type added
  later follows its conditions when the level is entered until it joins `LIVE_STORY_TYPES`
  (`level:check` warns when such an object reads a flag its own level sets).

### 9.6 The day, time and rest

The story's clock is the campaign's (on a single level, the level's). A new day starts when it
passes midnight going forward — time passing, the T key, the `time` command — and when the player
rests past one. The game setting the clock (a continued game's saved hour, a new journey's start)
and going into or out of a level with its own hour are not time passing: no day, no `time` events.
`rest` in a level with its own hour (an inn's room, `environment.clock: false`) keeps that hour and
moves the campaign's clock to the morning outside.

### 9.7 The party

The party's members are records in the story's state (`StoryState.party`, PARTY.md §2): the Party
writes them after every join, leave and rule change, conditions read them (`party`,
`party:<who>`), a campaign's save keeps them (atomic with the run, as every value), and a new
journey or a loaded save brings the party in line with them (`Game.syncParty`). A villager the
party holds is not there as the story stands (`present`): its `Npc` stays hidden on every level
and in every chapter variant, whatever its `when` / `unless` say, and comes back when it leaves.
`heal` refills the members too.

## 10. Checks, the editor, tests

- **`npm run level:check -- <level>`** lists a level's story problems (`StoryChecks.storyIssues`):
  parse errors with line numbers, conditions that do not parse, a reserved word as a bare flag
  (`when: gold`), events missing what their trigger needs, villagers, places and speakers the level
  does not have (compared as the game finds them: villagers by id, actor or name and story actors
  by id or name in any case), a story actor no villager of the level is (`walk` would stop there),
  `done:` keys that name no `once` event or block, `once` / `cycle` keys shared by two scripts,
  `party join` of no villager of this level and a party member (`party:<who>`, `party leave` /
  `rule` / `set` / `menu`) that is no villager of the level — of the campaign's levels in a
  campaign — nor an actor of the story files (warnings; an unknown class, preset, field or value
  is a parse error). A villager of another level of the campaign that a script stages (`walk`,
  `bark`, `camera` …) or gives a line to is no warning when the script tests `party:<it>` — in its
  lines, its event's `if` or the object's `when` (`StoryChecks.partyTests`): the member came along.
  The story states read `party` and `party:<who>` together (no member while `party = 0`, never
  more than `party` counts or 3; names in any case).
  Where conditions apply, the walk and the other level checks run once per **story state** (every
  combination of what the `when` / `unless` test): objects never there together do not overlap,
  what is reached only with a flag is a warning that names it —
  [CAMPAIGN_FORMAT.md §9](CAMPAIGN_FORMAT.md#9-checks).
- **`npm run level:check -- --campaign=<c>`** adds the story files and the links between them:
  undeclared items / quests / scripts / actors, quest stages (in every condition and script),
  `stage:` of an undeclared quest, `done:` keys across the campaign's levels and story events,
  `visited:` of no level, a chapter's `when` that reads `chapter` (an error — it would ask itself),
  `once` keys shared across levels and story files, items taken but never given, flags read but
  never set, travel targets and entrances, and a flag fixpoint from the start level (exits that
  can never open, flags only set where the player cannot get) —
  [CAMPAIGN_FORMAT.md §9](CAMPAIGN_FORMAT.md#9-checks).
- **The editor**: a script field (Tab / Shift+Tab indent at a line's start or on selected lines and
  move to the next field elsewhere, live errors, a pop-out editor with line numbers and the command
  reference), condition fields whose hint is what *Check for problems* says about them — one
  per-field function for both (`StoryChecks.conditionFieldIssues`), by the field's own rule
  (`when: gold` is an error, an event's `if: gold` is fine; an exit's `requires` is a condition
  field too), with what the object makes of it (an entry-only type — an enemy, a chest, a
  waystone — reading a flag its level sets, under the field that reads it; a "condition becomes true" event with a blank `if`) —, `event`
  and `marker` objects in both views (a `background` event dotted and tagged), the story problems
  in *Check for problems* — for a campaign's level against its story files and, as the campaign
  check does, `done:` keys against every level file's events and `once` keys (the open level's as
  edited; the files read again whenever a level of the campaign opens; all or nothing, so a file
  that cannot be read, or a campaign not read yet, reports nothing false) — and **View › Story
  preview…** (values like `bridge-mended`, `item:plank = 2`: what `when` / `unless` hide is
  hidden — and never selected; a double-click on its dimmed outliner row, or F on it, turns the
  preview off and selects it; stages and `level` read as in the game — a stage not reached counts
  as one past the reached ones, a chapter variant's `level` is its campaign level) —
  [LEVEL_EDITOR_GUIDE.md §5.5](../user/LEVEL_EDITOR_GUIDE.md#55-story-events-markers-scripts-and-the-story-preview).
- **`npm run story:test`** — the Node self-tests: the language, the story files and the checks
  (`tools/test-story.mjs`), then the runtime on a stub game — the values conditions read, the state
  and its save, the clock, triggers, runs, and the translations (`tools/test-story-runtime.mjs`):
  the content keys of every kind of script (per base, the parse cache, `call`, a chapter variant's
  own keys), the quest texts saved with their keys, ad-hoc lines in English as `nokey` misses, no
  miss for lines no window shows, parse errors reported once per script text, and the names a shop
  gave its items (`itemNames`).
- **`__game.story`** (`info`, `get`, `set`, `holds`, `give`, `run`, `fire`, `auto`, `skip`,
  `trace`, `journal`) and `state().story` —
  [AUTOMATION_API.md §3.7](AUTOMATION_API.md#37-window__gamestory-a-story-only); the scripted
  play-through `sandbox/story.play.json` (with `auto` answering choices).

## 11. Limits

KNOWN_ISSUES "Campaigns" and "Story" list them; in short: enemies, chests and waystones follow
their conditions on entering only; tiles, terrain and the water never change (chapter variants for
that) — an absent house leaves its bare footprint, an absent waterfall the water's step;
one main run at a time (background events beside it say and move, but never ask); `party join`
